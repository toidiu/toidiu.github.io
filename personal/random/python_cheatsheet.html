memory model / references

A variable is a NAME bound to a heap object, never the object itself. = copies the REFERENCE, never the object. No move, no ownership, no &/&mut/lifetimes — any number of names can alias one object; it lives until the last one drops (GC).

temp = ListNode(2)     # name temp -> NodeB
prev.next = temp       # prev.next aliases the SAME NodeB (no copy!)
prev = temp            # rebind the NAME prev; NodeB untouched
# this is why linked-list/tree `next`/`left` point to the real node, not a copy.

a = [1, 2, 3]
b = a                  # b and a -> SAME list
b.append(4)            # a is now [1,2,3,4] too — aliasing bites (see s06)
c = a[:]               # copy: slice/list()/dict()/copy.copy = new object
import copy
d = copy.deepcopy(a)   # recursive copy (nested structures)

# is  = "same object?" (identity)   ==  = "same value?" (calls __eq__)
x is y                 # True iff the SAME object in memory
x == y                 # value equality; list/dict/str compare by value
a is None              # ALWAYS use `is` for None (singleton)
# plain class with no __eq__: == falls back to identity, so == behaves like is.

Everything is a heap object — even int/float/bool/str. No primitives, no stack/heap choice, no Box/&/lifetimes. A variable is a pointer; the frame's stack slots hold pointers, the objects live on the heap. You can't place a value yourself.

type(5)                # <class 'int'> — 5 is a full object (PyLongObject), not raw
(5).bit_length()       # 3 — objects have methods; a bare int couldn't
# small-int cache: CPython pre-allocates ints -5..256 as shared singletons
a = 100
b = 100
a is b                       # True  — same cached object
a = 1000
b = 1000
a is b                       # False — two separate heap ints (usually)
a == b                       # True  — value equality still holds
# => `is` on ints/strs is a trap; use == for value, `is` only for None.
# deep recursion hits the C call stack -> RecursionError (~1000 frames);
# sys.setrecursionlimit(10_000) to raise it.

exceptions / control flow

Python signals failure by RAISING, not returning Result. Catch at the boundary.

class NotFoundError(Exception):   # custom error = subclass Exception
    pass

raise NotFoundError(k)            # throw (Rust: return Err / panic!)
raise ValueError("bad")           # builtin errors: ValueError, KeyError, TypeError,
                                  # IndexError, StopIteration, RuntimeError ...

try:
    return require_key(m, k)
except NotFoundError:             # catch ONE specific type
    return fallback
except (ValueError, KeyError) as e:   # catch several; `as e` binds the object
    print(str(e))                 # str(e) = message; e.args = tuple
except Exception as e:            # catch-all NORMAL errors (not Ctrl-C/SystemExit)
    ...                           # avoid bare `except:` — can't bind, swallows Ctrl-C
else:                             # ran only if NO exception (optional)
    ...
finally:                          # ALWAYS runs — cleanup (optional)
    ...

raise                             # bare re-raise inside except (keep traceback)
raise MyError("x") from e         # wrap, chaining the cause
# name the SPECIFIC type you expect; catch-all hides bugs.

with open("f") as fh:             # context manager — auto-cleanup (Rust: Drop/RAII)
    data = fh.read()              # fh closed on block exit, even on error

assert x > 0, "must be positive"  # raises AssertionError if false (tests/debug)

# pytest: assert an exception fires
import pytest
with pytest.raises(NotFoundError):
    require_key(m, "missing")

class / self

class Counter:
    def __init__(self, start: int = 0) -> None:  # constructor (Rust: new)
        self._data = start        # instance field; `self` is explicit ALWAYS
                                  # leading _ = "private" by convention only

    def inc(self) -> None:        # EVERY method takes self as 1st param
        self._data += 1           # (call site: c.inc() — self passed automatically)

    def get(self) -> int:
        return self._data

c = Counter(5)                    # no `new` keyword — just call the class
c.inc()                           # self = c, passed for you
c.get()                           # 6
# forgetting self in the def -> "takes 0 positional args but 1 was given"
isinstance(c, Counter)            # type check

heap (min-heap)

import heapq
h = []                        # a heap IS just a list — no Heap class
heapq.heappush(h, x)          # push
heapq.heappop(h)              # pop smallest
h[0]                          # peek min — O(1), doesn't remove
heapq.heapify(h)              # list -> heap, O(n), in place
heapq.heappushpop(h, x)       # push then pop, one step (faster)
heapq.nlargest(k, h)          # top k, biggest first — no negation needed
heapq.nsmallest(k, h)         # bottom k
len(h)                        # size; `if h:` tests non-empty

no key= on the heap itself — control order by what you push:

heapq.heappush(h, (freq, val))     # sort key = 1st tuple elem (min-heap)
heapq.heappush(h, (freq, i, val))  # add index tiebreaker if vals unorderable
heapq.nlargest(k, cnt, key=cnt.get)  # nlargest/nsmallest DO take key=

max-heap: negate on the way in and out (no built-in max-heap):

heapq.heappush(h, -x)         # store negatives
-heapq.heappop(h)             # negate back -> largest first
-h[0]                         # peek max
heapq.heappush(h, (-pri, item))  # tuple: negate the PRIORITY only
h = [-x for x in nums]
heapq.heapify(h)              # max-heapify: negate all first
# one-shot top-k? skip negation, use heapq.nlargest(k, nums)

size-k heap idiom (k largest, keep a MIN-heap of size k):

h = []
for x in nums:
    heapq.heappush(h, x)
    if len(h) > k:
        heapq.heappop(h)      # drop smallest -> heap holds the k largest
return sorted(h)              # drain ascending

queue

from collections import deque
q = deque([1, 2, 3])          # init from iterable
q.append(x)                   # add to back  — FIFO queue pair (with popleft)
q.popleft()                   # remove from front, O(1)  — FIFO queue pair
q.appendleft(x)               # add to front
q.pop()                       # remove from back
q[0]                          # peek front;  q[-1] peek back

queue (FIFO): add to the back with append, take from the front with popleft:

              front             back
  popleft() <-- [ 1, 2, 3 ] <-- append(x)

stack (LIFO): don't need deque — use a plain list (O(1) at the end):

                          top
  append(x) --> [ 1, 2, 3 ] <-- pop()
s = [1, 2, 3]                 # a list IS your stack
s.append(x)                   # push (onto the top/back)
s.pop()                       # pop the top — last in, first out
s[-1]                         # peek top

bisect (binary search)

Input list MUST be sorted!

import bisect
arr = [1, 3, 5, 7]              # setup: arr is SORTED
x = 4                           # setup: the target
bisect.bisect_left(arr, x)      # index: first i with arr[i] >= x (before dupes of x)
                                # x=2 (absent)  -> 1
                                # x=3 (present) -> 1
bisect.bisect_right(arr, x)     # index: first i with arr[i] >  x (after dupes of x)
                                # x=2 (absent)  -> 1
                                # x=3 (present) -> 2
bisect.insort(arr, x)           # in place, returns None — inserts at bisect_left(arr, x)
                                # x=2 -> [1, 2, 3, 5, 7]
                                # x=3 -> [1, 3, 3, 5, 7]

i = bisect.bisect_left(arr, x)  # membership check — arr[i] IS x when present, not arr[i+1]
i < len(arr) and arr[i] == x

patterns

Algorithm templates below (distinct from the language idioms above): each is a mental model + a skeleton with <-- knob labels + the knobs + a drill order. Learn the skeleton once; solve a family by changing knobs.

DP (solving in rungs: brute → memoize → optimize)

Don't jump to the optimal DP. Build it in rungs so the optimized form is derived, not memorized. Every search/DP/backtracking problem climbs the same ladder — the DP is just the brute force with repeated work cached.

Default to rung 2. The polished 1-D/2-D "state machine" solutions (rolling held/sold/rest, dp[i] += dp[i-coin], etc.) look like magic pulled from thin air — hard to derive under pressure, easy to get subtly wrong. Brute→memo is the reliable path: write the obvious recursion, then cache it. Same time complexity as the fancy version; you skip the "how did they SEE that?" step. Only climb to rung 3 when you actually need the space win or hit a recursion limit.

rung 1  BRUTE FORCE   exhaustive recursion / include-exclude decision tree.
                      correct first, ignore speed. this defines the STATE + transition.
rung 2  MEMOIZE       cache repeated (state) calls in a dict -> this IS top-down DP.
                      same recursion, ~O(states) time instead of O(2^n).  <- GO-TO
rung 3  BOTTOM-UP     fill a table / rolling array iteratively; drop recursion.
                      same time, better space, no recursion-depth limit. (optional finale)

Finding the STATE (rung 1) is the whole game: "standing here, what do I need to know to decide my next move?" Those facts ARE the memo key. Cooldown stock -> (day, holding, justsold). Stock-IV -> (day, holding, k_left). Partition -> (idx, remaining). Once you name the state, rungs 2 and 3 are mechanical.

Worked example — partition_equal_subset_sum ("can a subset sum to half?"):

# rung 1 — brute: include/exclude each number (0/1). O(2^n).
def can_reach(rem, idx):
    if rem == 0: return True
    if idx >= len(nums) or rem < 0: return False
    return can_reach(rem - nums[idx], idx + 1) or can_reach(rem, idx + 1)

# rung 2 — memoize: the state is exactly the args (rem, idx). O(n * half).
memo = {}                                  # look up -> compute -> STORE
def can_reach(rem, idx):
    if rem == 0: return True
    if idx >= len(nums) or rem < 0: return False
    key = (rem, idx)
    if key in memo: return memo[key]        # look up FIRST (after base cases)
    memo[key] = can_reach(rem - nums[idx], idx + 1) or can_reach(rem, idx + 1)
    return memo[key]                        # STORE before returning (easy to forget)

# rung 3 — bottom-up 1-D: the memo table collapses to one boolean row. O(half) space.
dp = [False] * (half + 1)
dp[0] = True
for num in nums:
    for s in range(half, num - 1, -1):      # DESCENDING -> each num used once (0/1)
        dp[s] = dp[s] or dp[s - num]
return dp[half]

Rung-2 gotchas (Python): assigning ans inside a nested fn makes it LOCAL — mutate an outer var via nonlocal, or (cleaner) return the bool up. And always STORE the recursive result in the memo, not just the base cases — else the cache does nothing and you're back to O(2^n). rung 3's descending sweep is the same "low cell still empty of this item -> used once" rule from the knapsack section.

Second example — cooldown stock (the rung-3 held/sold/rest state machine is the "magic" one; brute→memo gets there with zero cleverness):

# rung 1/2 — state = (day, holding, justsold). memo makes it O(states).
memo = {}
def go(day, holding, justsold):
    if day >= len(prices): return 0
    key = (day, holding, justsold)
    if key in memo: return memo[key]
    best = go(day + 1, holding, justsold)              # rest / do nothing
    if justsold:
        pass                                           # in cooldown -> can only rest
    elif holding:
        best = max(best, prices[day] + go(day + 1, False, True))    # SELL (justsold=True)
    else:
        best = max(best, -prices[day] + go(day + 1, True, False))   # BUY
    memo[key] = best
    return best
return go(0, False, False)
# memo turns 2^n into ~O(n): on a 16-day input, 131,071 brute calls -> 91 memoized.

The magic rung-3 form (held, sold, rest = max(held, rest-p), held+p, max(rest, sold)) is just this table filled bottom-up in O(1) space — same answer, but you'd never *derive* it cold. Reach for it only once the memo version is green and you want the space win.

backtracking

Four fixed parts every time: goal check → loop candidates → choose → recurse → un-choose. Only three knobs vary: the candidate loop, the recursion index, the prune.

def backtrack(start, path):
    if is_goal(path):            # record? subsets: ALWAYS (every node is a subset)
        result.append(path[:])   #          perms/combos: only when complete
        # return                 # extendable? subsets: NO return (keep growing)
                                 #              perms/combos: return (can't extend)
    for i in range(start, n):    # <-- knob: candidate loop (what can I add next?)
        if not valid(i):         # <-- knob: prune (skip choices that can't work)
            continue
        path.append(choice[i])   # choose
        backtrack(i + 1, path)   # <-- knob: recursion index (reuse + ordering)
        path.pop()               # un-choose: restore path for the sibling branch

is_goal + return per problem:

# subsets:          is_goal = True (record every node);  no return (extend to bigger)
# permutations:     is_goal = len(path) == n;            return (full perm can't grow)
# combination sum:  is_goal = remaining == 0;            return (target hit / overshoot)

the recursion-index knob — controls reuse + ordering:

backtrack(i + 1)     # combinations, NO reuse, no dup orders   (subsets, combos)
backtrack(i)         # combinations, reuse allowed             (combination_sum)
# permutations: drop `start`, loop ALL indices, skip taken ones with used[]

permutations variant (order matters -> used[] instead of start):

used = [False] * n
def backtrack(path):
    if len(path) == n:
        result.append(path[:])
        return
    for i in range(n):           # <-- knob: candidate loop (every index, not start..n)
        if used[i]:
            continue             # already in this permutation
        used[i] = True
        path.append(nums[i])
        backtrack(path)
        path.pop()
        used[i] = False          # un-choose BOTH

drills (advance_problems): subsets → combination_sum (reuse) → permutations (used[]) → word_search (grid)

intervals

Always sort first. The output the question wants picks the tool. This sort-by-end rule is interval-specific — general greedy (jump_game, gas_station, Kadane, partition_labels…) picks its sort key (or no sort at all) from whatever the locally-best choice needs, not from this table:

answer is a LIST of intervals     -> MERGE/EXTEND (default)  sort by start
answer is a COUNT of intervals    -> greedy by END           sort by end
answer is a COUNT of overlaps     -> sweep line              split endpoints

If the list is sorted by start, two intervals overlap when next_start <= cur_end.

ex: interval list (merge/extend, sort by start)

Use this for merged/inserted problems. Extend the last kept interval if the new one overlaps it, otherwise start a new block:

intervals.sort()                            # by start
res = []
for cur in intervals:
    if res:
        last = res[-1]
        if cur[0] <= last[1]:               # overlaps -> stretch end
            last[1] = max(last[1], cur[1])  # max: cur may sit INSIDE last
            continue
    res.append(cur[:])                      # first / no overlap -> new block
return res

Insert-interval is the same idea without the initial sort (input is already sorted): emit every interval that ends before the new one starts, fold every overlapping interval into the new one with min/max, then emit the rest.

ex: interval count (greedy)

For "minimum removals to avoid overlap" the interval that ends soonest always leaves the most room. This means we can be greedy and remove the interval that ends later. To achieve this we sort by END and check for overlaps:

# 0011222222112221111100
#     [    ]
#   [           ]
#             [      ]

intervals.sort(key=lambda x: x[1])          # by END
removed, end = 0, float('-inf')
for currs, curre in intervals:
    if currs >= end:                        # no overlap
        end = curre                         # keep
    else:
        removed += 1                        # drop
return removed

ex: overlap count (sweep line)

Use this for "minimum meeting rooms needed". Split starts and ends into two sorted lists and sweep across them, adding a room on each start and freeing one on each end:

# 0011222111111111110
#   [   ]
#     [      ]
#            [     ]

starts = sorted(i[0] for i in intervals)
ends   = sorted(i[1] for i in intervals)
rooms = peak = s = e = 0
while s < len(starts):
    if starts[s] < ends[e]:                 # a start comes next -> +1 room
        rooms += 1
        s += 1
        peak = max(peak, rooms)
    else:                                    # an end comes next -> free a room
        rooms -= 1
        e += 1
return peak

This is equivalent to a min-heap of end times, where the heap size is the room count. The simpler "can one person attend all meetings?" question only needs a start-sort: return False on the first start < prev_end.

drills: merge → insert → non_overlapping (end) → meeting_rooms → meeting_rooms_ii (sweep) → min_arrows_burst_balloons (end) → min_interval_include_query (sweep + heap)

linked_list

dummy node — when to use it

A dummy node is a throwaway ListNode() whose .next points at the real head. It exists to kill the "is this the head?" special case: with a dummy, prev always points at a real node, so prev.next = x works uniformly whether x lands at position 0 or position 50.

use a dummy when:  the head itself might be removed, replaced, or built up
                    from nothing (the result list starts empty)
skip the dummy when:  you're only ever reading/reversing in place and the
                    original head always survives (e.g. reverse_linked_list,
                    has_cycle) — nothing to special-case
dummy = ListNode(0, head)     # dummy.next -> real head
prev = dummy
while ...:
    ...
    prev.next = ...           # never need an `if prev is None: head = x` branch
return dummy.next              # unwrap — real head may have changed

Signature tells: if the problem is "remove/insert/merge" (remove_nth_from_end, merge_two_lists, merge_k_lists, partition), reach for a dummy first. If it's "reverse/traverse/detect" in place, you probably don't need one.

cycle detection

Floyd's tortoise & hare — full section below (## floyd's cycle detection). Detect: fast/slow pointers meet iff there's a cycle. Locate entrance: reset one to head, step both by 1. Skip a dummy node here — you only read/traverse.

floyd's cycle detection

Two pointers on the same sequence at different speeds. Works on anything with a "next" step: a linked list (node.next) OR an array read as a functional graph (i -> nums[i]). Detects a cycle in O(1) space, and pinpoints where it starts.

Mental model: slow steps 1, fast steps 2. If there's a cycle, fast is inside it lapping slow; the gap shrinks by exactly 1 each step, so it MUST hit 0 — they meet. No cycle → fast runs off the end (None, or out of bounds).

phase 1 — detect (do they meet?)

slow = fast = head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
    if slow is fast:            # gap hit 0 -> cycle exists
        break
if not fast or not fast.next:
    return False                # fast fell off the end -> no cycle

phase 2 — locate the entrance (where does the loop begin?)

After they meet, reset ONE pointer to head, then step both by 1. They meet again exactly at the cycle entrance:

  WHY IT WORKS

         -------
        |       |
  S-----M       |
        |       |
         -----O-

    slow: move 1
    fast: move 2

    S..M = x (distance)  head -> entrance
    M..O = y (distance)  entrance -> meeting point
    O..M = z (distance)  meeting point -> entrance (rest of loop)

    slow travels distance = x + y
    fast travels distance = x + 2y + z

    2 (x + y) = x + 2y + z
    2x + 2y = x + 2y + z
    2x  = x + z
    x = z
slow2 = head
while slow2 is not slow:
    slow = slow.next
    slow2 = slow2.next
return slow2                    # the entrance node

array variant (find_duplicate)

Treat nums[i] as "next pointer" i -> nums[i]. With values in [1, n] and one duplicate, two indices point at the same value → that value is a node with two in-edges → the cycle ENTRANCE. So phase-1 detect + phase-2 locate returns the duplicate, in O(1) space without mutating the array (advance_problems/linked_list/p09_m_find_duplicate.py).

slow = fast = nums[0]
while True:                     # a cycle is guaranteed here, so no end-check
    slow = nums[slow]
    fast = nums[nums[fast]]
    if slow == fast:
        break
slow2 = nums[0]
while slow2 != slow:
    slow = nums[slow]
    slow2 = nums[slow2]
return slow                     # the duplicate value = cycle entrance

when to use: "does a linked list have a cycle?", "where does it start?", "find the duplicate without extra space / without mutating". O(1) space is the tell — a hash set also detects cycles but costs O(n).

drills: linked_list_cycle (detect) → find_duplicate (array-as-list + entrance)

binary_search

Two shapes, same start/end/mid variables — the loop condition and what you do with mid on a "keep searching" step are the knobs.

exact match (binary_search, search_rotated, time_based_kv)

start <= end, both bounds still candidates, so a miss excludes mid entirely (mid - 1 / mid + 1):

start, end = 0, len(nums) - 1
while start <= end:
    mid = start + (end - start) // 2   # avoids overflow (not a Python issue, but habit)
    mid_val = nums[mid]

    if mid_val == target:
        return mid
    elif target < mid_val:
        end = mid - 1                  # <-- knob: exclude mid, go left
    else:
        start = mid + 1                # <-- knob: exclude mid, go right
return -1

Rotated array adds one knob up front: figure out which half is sorted, then apply the plain in-range check to decide which side to keep:

if nums[start] <= mid_val:             # left half is sorted
    if nums[start] <= target < mid_val:
        end = mid - 1
    else:
        start = mid + 1
else:                                   # right half is sorted
    if mid_val < target <= nums[end]:
        start = mid + 1
    else:
        end = mid - 1

search the answer / boundary (find_min_rotated, koko_eating_bananas)

start < end, mid might still BE the answer, so the "keep" branch narrows to end = mid (never mid - 1 — that would throw away a still-valid candidate). Loop ends when start == end, which IS the answer — no -1 sentinel, no post-loop lookup.

start, end = lo, hi                    # search space of ANSWERS, not array indices
while start < end:
    mid = start + (end - start) // 2
    if is_solution(mid):               # <-- knob: feasibility predicate
        end = mid                      # mid still works -> keep it, narrow right side
    else:
        start = mid + 1                # mid doesn't work -> exclude it
return start                           # start == end: the smallest feasible value

find_min_rotated uses nums[mid] > nums[end] as the predicate (mid is on the "still rotated, min is further right" side); koko_eating_bananas uses a feasibility function (total hours at rate mid <= h) over the answer range [1, max(piles)] instead of over array indices at all — the array being searched doesn't have to be the input array.

drills: binary_search -> search_rotated -> find_min_rotated -> time_based_kv -> koko_eating_bananas -> search_2d_matrix -> median_two_sorted

dp_1d

Core shape: dp[i] = best answer (or yes/no) for the prefix ending at i, defined in terms of dp[i-1], dp[i-2], or some earlier dp[j]. Once you see that only the last 1-2 slots are ever read, roll the array down to plain variables — O(1) space instead of O(n).

take-or-skip (house_robber)

At each index, either skip it (carry dp[i-1] forward) or take it (x + dp[i-2], since taking x locks out its immediate neighbor). Rolling-variable form — no array needed:

prev2 = prev1 = 0
for x in nums:
    prev2, prev1 = prev1, max(prev1, prev2 + x)  # <-- knob: recurrence
return prev1

circular constraint -> run the linear version twice (house_robber_ii)

A circular "no two adjacent" constraint only ever rules out ONE pair: (first, last). So a valid selection skips house 0 entirely, or skips house n-1 entirely — never both ends at once. Run the plain linear dp on nums[1:] and on nums[:-1], take the max; no wraparound special-casing needed.

return max(rob_linear(nums[1:]), rob_linear(nums[:-1]))

expand around center (longest_palindromic_substring, palindromic_substrings)

A palindrome is built outward from its center, and there are 2n-1 centers: n single-char (odd length) + n-1 between-char (even length). One helper handles both — call it twice per index with different starting bounds:

def expand(l, r):                # <-- knob: what to do with each valid span
    while l >= 0 and r < len(s) and s[l] == s[r]:
        l -= 1
        r += 1
    return l + 1, r - 1          # inclusive bounds of the palindrome found

for i in range(len(s)):
    lo, hi = expand(i, i)        # odd center
    lo2, hi2 = expand(i, i + 1)  # even center
    # <-- knob: track longest span vs. count every span found

longest_palindromic_substring keeps the longest span; palindromic_substrings counts every span expand returns (every expansion IS a valid palindrome).

prefix reachability (word_break)

dp[i] = "can the prefix s[:i] be fully segmented?" dp[0] = True (empty prefix, vacuously). For each i, scan earlier split points j < i: if dp[j] is True and s[j:i] is a dictionary word, dp[i] is True — one witness is enough, no need to find every way.

words = set(word_dict)           # O(1) membership, not O(k) list scan
dp = [False] * (len(s) + 1)
dp[0] = True
for i in range(1, len(s) + 1):
    for j in range(i):
        if dp[j] and s[j:i] in words:   # <-- knob: transition condition
            dp[i] = True
            break
return dp[-1]

Same shape covers decode_ways (dp[i] built from dp[i-1]/dp[i-2] depending on whether s[i-1] and s[i-2:i] decode validly) and coin_change (dp[i] = min coins for amount i, transition loops over coin denominations instead of split points).

drills: climbing_stairs -> house_robber -> house_robber_ii -> longest_palindromic_substring -> palindromic_substrings -> decode_ways -> coin_change -> maximum_product_subarray -> word_break -> longest_increasing_subsequence -> min_cost_climbing_stairs -> partition_equal_subset_sum (0/1 knapsack: dp[target] reachable via subset sums)

knapsack (coin change family)

dp[a] over a 1-D amount array, filled by looping items (coins). TWO loop knobs decide the whole meaning — get them right and the problem is solved:

item loop position   coins OUTER -> COMBINATIONS ([1,2]==[2,1], count once)
                     amount OUTER -> PERMUTATIONS (ordered, [1,2]!=[2,1])
amount direction     ascending  -> UNLIMITED reuse of each item (unbounded)
                     descending -> use each item AT MOST once  (0/1 knapsack)

The two core forms are IDENTICAL except the inner range direction — that one flip is the whole unbounded-vs-0/1 distinction:

One sentence summary You always read a lower cell (dp[a-item]) to fill a higher one.

  • Ascending fills low cells first → the low cell already contains this item → using it again = reuse.
  • Descending fills high cells first → the low cell is still empty of this item → used once.

unbounded — reuse each item freely (amount ASCENDING)

dp = [0] * (amount + 1)
dp[0] = 1
for item in items:
    for a in range(item, amount + 1):    # ASCENDING (low -> high)
        dp[a] += dp[a - item]            # dp[a-item] ALREADY updated this pass -> reuse item
return dp[amount]

0/1 — use each item at most once (amount DESCENDING)

dp = [0] * (amount + 1)
dp[0] = 1
for item in items:
    for a in range(amount, item - 1, -1):  # DESCENDING (high -> low)
        dp[a] += dp[a - item]              # dp[a-item] still LAST pass's value -> item used once
return dp[amount]

count combinations (coin_change_ii): coins outer, amount ascending

dp = [0] * (amount + 1)
dp[0] = 1                        # one way to make 0: the empty combination
for coin in coins:              # OUTER -> one coin fully before next = fixed order
    for a in range(coin, amount + 1):   # ascending -> dp[a-coin] already used this coin
        dp[a] += dp[a - coin]   # <-- knob: += counts ways
return dp[amount]
# change(5,[1,2,5]): [1,1,2,2,3,3]->after coin5-> dp[5]=4  (11111,1112,122,5)

fewest coins (coin_change): coins can be inner or outer, min not count

dp = [float('inf')] * (amount + 1)
dp[0] = 0
for a in range(1, amount + 1):
    for coin in coins:
        if coin <= a:
            dp[a] = min(dp[a], dp[a - coin] + 1)  # <-- knob: min+1 counts coins
return dp[amount] if dp[amount] != float('inf') else -1
# order doesn't matter here: min over all coins per amount, reuse allowed (ascending)

subset-sum / 0/1 (partition_equal_subset_sum): items outer, amount DESCENDING

dp = [False] * (target + 1)
dp[0] = True
for num in nums:                # each item used at most once
    for a in range(target, num - 1, -1):   # DESCENDING -> can't reuse num this pass
        dp[a] = dp[a] or dp[a - num]
return dp[target]

drills: coin_change (min) -> coin_change_ii (count combos) -> partition_equal_subset_sum (0/1) -> target_sum (0/1 w/ +/- signs)

weighted graphs (dijkstra / prim / bellman-ford)

All three relax edges until every node settles. They differ in what the number attached to a node MEANS, and that one difference is the whole section:

dijkstra      dist[v] = cheapest total cost from the source to v
prim          key[v]  = cheapest single edge attaching v to the tree
bellman-ford  dist[v] = cheapest cost to v using <= r edges so far

Shared setup — build adjacency once, defaultdict so a sink node reads back empty instead of raising:

from collections import defaultdict
outgoing = defaultdict(list)           # u -> [(v, weight)]
for u, v, w in edges:
    outgoing[u].append((v, w))
    # outgoing[v].append((u, w))       # undirected: add BOTH directions

Unreachable is float('inf'), and it survives arithmetic (inf + 5 == inf), which is why it beats None as a sentinel. Watch for 1-indexed node labels (1..n), common in this category — size any list-based table n + 1.

dijkstra — cheapest path from one source (network_delay_time, swim_in_water)

Min-heap ordered by cost. Pop the cheapest unsettled node, and its cost is final: with non-negative weights no longer route can ever undercut it. Negative weights break that promise — use bellman-ford there instead.

frontier = [(0, source)]               # (cost, node) — COST FIRST, the heap sorts on it
settled = {}                           # node -> final cost; also the visited set

while frontier:
    cost, node = heapq.heappop(frontier)

    if node in settled:                # stale: a node is pushed once per inbound
        continue                       # edge, only the first (cheapest) pop counts
    settled[node] = cost

    for nb, w in outgoing[node]:
        if nb not in settled:
            heapq.heappush(frontier, (cost + w, nb))

Bottleneck variant (swim_in_water): a route costs its WORST edge, not its total, so swap the one relaxation line. Everything else is untouched:

heapq.heappush(frontier, (cost + w, nb))        # dijkstra: sum along the route
heapq.heappush(frontier, (max(cost, w), nb))    # bottleneck: worst on the route

Gotchas:

heapq.heappush(frontier, (node, cost))   # WRONG — orders by node label, not cost
if not cost: continue                    # WRONG — a 0-weight edge is a real edge

There is no decrease-key in heapq. Push duplicates and drop the stale ones on pop ("lazy deletion") — that if node in settled line IS the algorithm, not an optimization.

prim — cheapest tree touching every node (min_cost_connect_points)

Same loop as dijkstra with ONE line changed. Dijkstra asks "how far is this node from the source"; prim asks "how cheap is it to attach this node to what I've already built", so the running cost is not carried forward:

heapq.heappush(frontier, (cost + w, nb))   # dijkstra: distance from the source
heapq.heappush(frontier, (w, nb))          # prim:     cost to attach, standalone

Total is accumulated as nodes join, and the loop runs until all n are in:

in_tree = [False] * n
frontier = [(0, 0)]                    # (attach cost, node) — node 0 is an arbitrary root
total = attached = 0

while attached < n:
    cost, node = heapq.heappop(frontier)
    if in_tree[node]:
        continue
    in_tree[node] = True
    total += cost                      # <-- accumulate, vs dijkstra recording a distance
    attached += 1
    for nb, w in outgoing[node]:
        if not in_tree[nb]:
            heapq.heappush(frontier, (w, nb))

Undirected only — an MST has no notion of direction. On a COMPLETE graph (every pair connectable, as with points on a plane) skip the adjacency dict entirely and compute weights on the fly:

for other in range(n):                 # O(n^2) edges, never materialized
    if not in_tree[other]:
        w = abs(x - px[other]) + abs(y - py[other])
        heapq.heappush(frontier, (w, other))

Kruskal is the other MST route: sort all edges, union-find, keep an edge only when it joins two components. Prefer prim on dense graphs, kruskal when the edge list is already given (see redundant_connection for the union-find shape).

bellman-ford — negative weights, or a cap on hops (cheapest_flights)

No heap, no settled set. Just relax EVERY edge, n - 1 times over — after round r, dist[v] is the best cost reachable in at most r edges. Slower at O(V*E), but nothing about it assumes non-negative weights:

dist = [float('inf')] * n
dist[source] = 0
for _ in range(n - 1):                 # a shortest path has at most n-1 edges
    for u, v, w in edges:
        if dist[u] + w < dist[v]:
            dist[v] = dist[u] + w

An n-th round that still improves something proves a negative cycle:

for u, v, w in edges:
    if dist[u] + w < dist[v]:
        return "negative cycle"

Hop-limited variant (cheapest_flights): "at most k stops" means at most k+1 EDGES, so run exactly k + 1 rounds. Now the snapshot matters — relax against last round's prices, or a single round chains several edges together and quietly overshoots the budget:

for _ in range(k + 1):
    snapshot = dist[:]                 # read from `dist`, write to `snapshot`
    for u, v, w in edges:
        if dist[u] != float('inf') and dist[u] + w < snapshot[v]:
            snapshot[v] = dist[u] + w
    dist = snapshot

That round-count IS the edge budget, which is what makes bellman-ford the right tool here — dijkstra settles a node at its cheapest price with no idea how many edges that took, and the cheap route can be the one that blows the budget.

picking one

non-negative weights, one source, shortest path   -> dijkstra
route cost is its worst edge, not its sum         -> dijkstra, max instead of +
connect all nodes as cheaply as possible          -> prim (dense) / kruskal (edge list)
negative weights, or a limit on edges used        -> bellman-ford
unweighted (every edge costs 1)                   -> plain BFS, no heap needed

Last line is worth a beat: a heap on an unweighted graph is wasted work, and BFS from every source at once ("multi-source BFS") solves the whole walls_and_gates / rotting_oranges family in one pass.

drills: min_cost_connect_points -> network_delay_time -> cheapest_flights -> swim_in_water
